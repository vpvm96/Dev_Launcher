# Dev Launcher

여러 프로젝트를 그룹으로 묶어 로컬 서버, 실행 스크립트, 환경변수를 관리하는 macOS 앱입니다. Electron과 일반 JavaScript로 구성했습니다.

## 설치와 사용

[최신 릴리스](https://github.com/vpvm96/Dev_Launcher/releases/latest)에서 Apple Silicon Mac용 DMG 또는 ZIP을 다운로드하고 `Dev Launcher.app`을 응용 프로그램 폴더로 옮깁니다.

1. 그룹 추가로 함께 사용할 프로젝트를 묶습니다.
2. 프로젝트 추가에서 내 컴퓨터의 프로젝트 폴더를 선택합니다.
3. DEV·PROD 실행 스크립트를 선택하거나 **직접 입력**으로 `sh ./start.sh` 같은 명령을 입력하고 환경 파일을 지정합니다.
4. 선택 실행 또는 개별 실행·종료·재시작을 사용합니다.
5. 환경 설정에서 실행 스크립트와 개인 환경값을 수정합니다. 실행 중이면 저장 후 재시작할 수 있습니다.

프로젝트 코드와 환경 파일, 해당 프로젝트에 필요한 Node.js 또는 JDK·빌드 도구·설치된 의존성을 별도로 준비해야 합니다. DEV·PROD는 로컬 실행에 사용할 환경 설정이며, 운영 서버 배포 기능이 아닙니다.

`실행 후 브라우저 열기`는 모든 그룹에 적용되고 기본으로 켜져 있습니다. 서버 포트가 열리면 브라우저를 한 번 엽니다. 최대 2분 동안 기다린 뒤 로그에 안내합니다. Vite·CRA의 자체 자동 열기는 런처에서 제어합니다.

프로젝트 종료 시 로그가 초기화됩니다. 앱 창을 닫거나 앱 재시작을 누르면 런처에서 실행한 서버도 종료됩니다. **메뉴 바 상주**를 켜면 창을 닫아도 서버가 유지되고, 메뉴 바 아이콘에서 실행 상태 확인과 실행·종료·열기를 할 수 있습니다. 기존 터미널에서 실행한 서버는 관리하지 않습니다.

그룹은 이름 변경, 순서 변경, 삭제가 가능하며 같은 프로젝트 폴더를 여러 그룹에 등록할 수 있습니다. 프로젝트 카드의 화살표로 순서를 바꾸고, Finder·터미널·VS Code 버튼으로 프로젝트 폴더를 바로 열 수 있습니다. 창 크기와 위치는 다음 실행 시 복원됩니다.

## 실행 순서와 자동 재시작

환경 설정의 **프로젝트 옵션**에서 설정합니다. `앞 프로젝트 준비 후 실행`을 켜면 선택 실행 시 목록에서 바로 앞 프로젝트의 포트가 열릴 때까지 최대 2분 기다린 뒤 시작합니다. 백엔드 다음에 프론트를 켤 때 사용하세요. `비정상 종료 시 자동 재시작`을 켜면 프로세스가 예기치 않게 종료될 때 macOS 알림을 보내고 연속 3회까지 다시 시작합니다. 옵션을 끄면 알림만 보냅니다.

## 실행 환경 추가

기본 환경은 DEV·PROD입니다. 환경 설정의 **실행 환경**에서 `staging`처럼 영문 소문자 이름으로 환경을 추가할 수 있습니다. 환경마다 실행 스크립트, 환경 파일, 개인 환경값, SSH 터널을 따로 저장합니다. 추가한 환경은 카드의 환경 선택과 그룹 환경에 나타나며, DEV는 삭제할 수 없습니다.

## 로그

로그 창은 터미널 색상 코드를 색상으로 표시하고 커서 이동 같은 제어 문자는 제거합니다. 검색으로 해당 문구가 포함된 줄만 볼 수 있고, 복사 버튼은 색상 코드를 제외한 전체 로그를 클립보드에 넣습니다. 지우기는 실행 중인 프로세스를 유지한 채 보관 중인 출력만 비웁니다.

## Node 버전

프로젝트에 `.nvmrc` 또는 `.node-version`이 있으면 nvm(`~/.nvm`) 또는 fnm(`~/.local/share/fnm`, `~/Library/Application Support/fnm`)에 설치된 해당 버전을 찾아 우선 사용하고 로그에 안내합니다. `20`처럼 메이저만 지정하면 설치된 가장 높은 버전을 사용합니다. 설치된 버전이 없거나 `lts/*` 같은 별칭이면 기본 Node를 사용하고 로그에 알립니다.

## 설정 내보내기와 가져오기

왼쪽 아래 **내보내기**는 그룹과 프로젝트 구성(이름, 경로, 실행 스크립트, 환경 파일, 실행 환경, 옵션)을 JSON으로 저장합니다. 개인 환경값과 SSH 터널 설정은 포함하지 않습니다. **가져오기**는 파일의 그룹을 새 그룹으로 추가하며, 이 Mac에 없는 폴더는 건너뛰고 결과를 알려 줍니다.

## 스크립트 직접 입력

프로젝트 연결 또는 환경 설정의 실행 스크립트 목록에서 **직접 입력**을 선택하세요. DEV·PROD별로 명령을 따로 저장할 수 있습니다. `package.json`이나 Spring Boot 설정이 없는 일반 폴더도 연결할 수 있습니다.

명령은 선택한 프로젝트 폴더를 기준으로 실행합니다. 예를 들어 `sh ./start.sh`, `bash ./scripts/dev.sh`, 공백이 있는 경로는 `sh "./scripts/start server.sh"`로 입력합니다. 환경 파일과 개인 환경값은 스크립트에 전달됩니다. 직접 입력한 명령과 파일 내부의 명령은 그대로 실행되므로, 해당 스크립트가 수행하는 파일 변경도 적용됩니다. 서버는 백그라운드로 분리하지 않고 실행해야 런처에서 종료할 수 있습니다. 정상 종료한 일회성 스크립트는 중지 상태로 표시하며 출력은 로그에서 확인합니다. 브라우저 열기가 필요하면 `PORT` 또는 `SERVER_PORT` 환경값을 지정하세요.

## Java·타임리프 프로젝트

`package.json`이 없으면 `build.gradle`, `build.gradle.kts`, `pom.xml`에서 Spring Boot 실행 플러그인을 찾습니다. Gradle은 `bootRun`, Maven은 `spring-boot:run`을 DEV·PROD 실행 스크립트로 자동 설정합니다. 프로젝트의 `gradlew`·`mvnw`를 우선 사용하고, 없으면 시스템의 `gradle`·`mvn`을 사용합니다. Gradle 실행에는 `--no-daemon`을 적용합니다. JDK와 필요한 빌드 도구는 별도로 준비해야 합니다.

DEV·PROD가 Spring 프로필을 자동으로 바꾸지는 않습니다. 환경 설정에서 필요에 따라 `SPRING_PROFILES_ACTIVE`를 지정하세요. `.properties`·YAML 설정은 Spring이 직접 읽으며 런처의 환경 파일 입력란에는 `.env` 형식만 지정합니다. 포트는 개인 환경값 `SERVER_PORT`를 우선하고, 없으면 `src/main/resources`의 `application.properties`·`application.yml`에서 `server.port`를 읽습니다. `${SERVER_PORT:8080}` 형태는 기본값을 사용하며, 설정이 없으면 Spring Boot 기본 포트 8080으로 브라우저 열기와 포트 충돌 검사를 수행합니다.

`target`·`build` 대신 실행할 모듈의 빌드 설정이 있는 폴더를 선택하세요. 정적 파일에 직접 선언된 실행 플러그인을 감지하며, 부모 프로젝트에서 상속하거나 별도 스크립트·버전 카탈로그로 적용하는 플러그인, 비활성 플러그인 선언 및 별도 Tomcat 배포는 자동 감지 대상이 아닙니다. Node 설정과 Java 설정이 함께 있으면 `package.json`을 우선합니다.

실행 명령 참고 문서. [Spring Boot Gradle](https://docs.spring.io/spring-boot/gradle-plugin/running.html), [Spring Boot Maven](https://docs.spring.io/spring-boot/maven-plugin/run.html).

## 개인 설정

기본 환경 파일과 개인 설정을 합쳐 자식 프로세스에 전달합니다. 프로젝트의 `.env`와 원본 환경 파일을 수정하지 않습니다. 개인 설정은 `~/Library/Application Support/Dev Launcher`에 저장되며 배포 앱에 포함되지 않습니다. 기존 사용자 설정은 앱 업데이트 후에도 유지됩니다. 직접 설정 체크를 꺼도 마지막으로 입력한 값은 보관되며, 다시 체크하면 재사용할 수 있습니다. 체크를 끈 값은 서버에 적용하지 않습니다. 환경 설정의 값 표시는 기본으로 켜져 있으며 필요하면 끌 수 있습니다.

감지된 스크립트를 선택한 경우 환경 파일 로더를 분리해 실제 서버 명령을 실행하므로 npm pre/post 스크립트는 실행하지 않습니다. 단순 npm/yarn/pnpm 별칭은 지원하며, 복합 패키지 명령은 지원하지 않습니다.

## SSH 터널 연결

프로젝트의 DEV 또는 PROD를 선택한 뒤 **환경 설정 → SSH 터널 사용**을 켭니다. PEM 키 파일, SSH 서버 주소·사용자·포트, 로컬 포트와 원격 DB 주소·포트를 입력하세요. **DB 주소 적용**을 누르면 개인 환경변수에 `DB_HOST=127.0.0.1`, `DB_PORT=로컬 포트`가 입력됩니다. 설정을 저장하고 프로젝트를 실행하면 터널 연결 확인 후 서버를 시작합니다. `.dev.env` 등 원본 환경 파일은 변경하지 않습니다.

PEM은 복사하거나 내용을 저장하지 않고 이 Mac의 경로만 보관합니다. 키 파일 권한은 `600` 또는 `400`이어야 합니다. SSH는 비대화형으로 실행하며 기존 `known_hosts`에 등록된 서버만 연결합니다. 처음 접속하는 서버는 터미널에서 서버 지문을 확인하고 등록해 주세요. 비밀번호나 키 암호 입력이 필요한 경우 런처에서는 연결할 수 없습니다. 사용자 SSH 설정 파일 대신 화면에 입력한 설정을 사용합니다.

서버 종료·재시작·앱 종료 시 터널도 닫습니다. SSH 연결이 끊어지면 서버를 종료하고 오류를 표시합니다. 로컬 포트가 이미 사용 중이면 실행하지 않으므로, 수동으로 열어 둔 터널은 먼저 종료하거나 다른 로컬 포트를 지정하세요. 터널 준비 확인은 SSH 포워딩 설정까지이며 실제 DB 로그인 성공 여부는 서버 로그에서 확인합니다.

원격 DB에 대한 데이터 변경은 해당 DB에 반영됩니다. DEV와 PROD 터널 설정은 따로 저장되며, 터널을 끄더라도 직접 적용한 `DB_HOST`와 `DB_PORT` 개인 설정은 유지되므로 필요하면 체크를 해제하세요.

## 앱 업데이트

앱 실행 후와 6시간마다 GitHub Releases에서 새 버전을 확인합니다. 왼쪽 아래 업데이트 확인에서 수동 확인도 가능합니다. 다운로드 후 설치 후 재시작을 누르면 관리 중인 서버를 종료하고 업데이트를 설치합니다. 자동 다운로드나 종료 시 자동 설치는 하지 않습니다.

자동 업데이트 기능이 없던 1.0.0 사용자는 1.1.0 이상을 한 번 직접 설치해야 합니다. 이후에도 같은 앱 ID와 개발자 서명으로 배포합니다.

## 로컬 개발

```sh
npm ci
npm start
npm test
npm run test:ui
```

테스트는 별도의 임시 설정과 프로젝트를 사용합니다. 실제 등록된 서비스를 실행하지 않습니다.

## 배포 담당자

유효한 Developer ID Application 인증서와 개인 키가 Mac 키체인에 있어야 합니다. Apple 공증용 인증은 터미널에서 한 번 저장합니다. 앱 전용 암호는 대화형 입력으로 넣고 파일이나 Git에 저장하지 않습니다.

```sh
xcrun notarytool store-credentials dev-launcher
```

버전을 올리고 변경 사항을 커밋한 뒤 `main`에 푸시합니다. 다음 명령은 서명·공증된 DMG와 ZIP, 업데이트 메타데이터를 `release` 폴더에 생성합니다.

```sh
npm run package:release
npm run release:publish
```

`release:publish`는 현재 커밋이 `origin/main`과 일치하는지, 버전과 공증 상태를 확인한 다음 GitHub Releases 초안에 업로드하고 공개합니다. GitHub 인증은 배포 담당자의 `gh auth login` 설정을 사용합니다. 사용자 앱에 GitHub 토큰을 넣지 않습니다.

`npm run package`는 서명만 하는 로컬 검증용입니다. 공증하지 않으므로 공개 릴리스에 사용하지 않습니다.

참고 문서. [Electron 보안](https://www.electronjs.org/docs/latest/tutorial/security), [자동 업데이트](https://www.electron.build/v26/docs/features/auto-update/), [Apple 공증](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution).
